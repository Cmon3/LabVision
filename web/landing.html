The problem

QC, food and water labs count colonies by eye. In pharma, that count decides whether a batch is released. It is slow, subjective, and hard to audit.

How it works

⌨️

1. Ask

Type or speak a plain request — “count colonies larger than 2 mm”, “is this plate countable?” SAM 3.1 prompt is chosen by Muse Spark Open.

🔬

2. Agent plans, SAM finds, Python measures

The agent checks quality (blur, glare), SAM 3.1 finds colonies, Python measures areas and diameters in px or mm. Each step streams live with its badge: model, rule, or human.

✅

3. Review, click to fix, export

Masks and boxes on a canvas, measurements table, QC trace, and report. Click to add or remove a colony, download CSV — every edit is logged separately.

Results

11.8% average error on 20 plates it never saw, 7 exact. Same data, different prompt:

“bacterial colony” — 99% error
“round spot” — 11.8% error (benchmarked)

Full tables in bench/RESULTS.md — AGAR 20 test plates, BBBC005 w1 MAE 5.48 / w2 18.95.

Built with Meta

SAM 3.1 — Meta Model API, one-bit masks Muse Spark Open — open weights via Baseten Muse Voice Transcribe — WAV mono 24 kHz, hands-free

Open-weights bonus track. Only public or synthetic data goes to the model APIs.

What it won’t do

  • No organism names. Muse Spark Open declined on biological-risk policy — we kept that line.
  • No mixed-culture flag. It scored 80% vs 90% always-pure baseline on test, so we removed it.
  • >300 colonies = TNTC. “Too numerous to count: dilute and re-plate” — the honest answer for dense plates.

Research and QC quantification — not a clinical device. Numbers from Python, interpretation from the model.
